# 汇金证金及其关联公司持仓追踪

一个纯静态、可自托管的 **A 股 ETF 国家队持仓追踪仪表盘**。聚焦中央汇金（汇金投资 / 汇金资管）、中国国新（国新投资）等"国家队"主体在 ETF 十大持有人中的直接持仓，并结合行情、份额、资金流数据，呈现其增持 / 减持动向。

> ⚠️ 本项目为 **AI 工具生成的演示性作品**，仅用于技术研究与学习参考，**不构成任何投资建议**。详见 [免责声明](免责声明.md)。

---

## 一、项目简介

"国家队"资金（汇金、证金及其关联主体）的 ETF 持仓变动，是观察市场托底与配置方向的重要信号。但这类信息分散在基金年报 / 半年报的十大持有人段落中，且缺乏连续的时间序列视图。

本项目把以下信息整合到一个可交互的仪表盘里：

- **持仓披露**：汇金投资、汇金资管、国新投资直接持有的 ETF 及占比 / 金额（基于定期报告）。
- **量价数据**：ETF 前复权价、成交额、份额、申购赎回净额、净申赎金额占指数成交额比。
- **对照基准**：部分 ETF 叠加对应指数（沪深 300、中证 500、科创 50 等）做形态对照。

当前共追踪 **42 只 A 股 ETF**（宽基 + 行业），数据来源为公开网络接口。

---

## 二、功能特性

- 📊 **五联日度图**：价格、成交额、份额、申购赎回份额、净申赎 / 指数成交额占比。
- 🔍 **ETF 列表与分组**：按宽基 / 行业分组，支持切换与快捷筛选。
- 🗓️ **区间缩放与拖拽**：时间轴可框选区间、拖动窗口、一键回到最新。
- 📈 **区间趋势看板**：按 ETF / 合计展示价格变动、成交额分位、净份额变动分位、净申赎金额等。
- 🌗 **日间 / 夜间模式**：默认日间，可一键切换（选择记忆于浏览器本地）。
- 🔄 **每日自动刷新**：通过 GitHub Actions 每日 20:00（北京时间）自动拉取最新数据并发布。
- 💻 **本地零依赖运行**：数据刷新脚本仅用 Python 标准库，无需安装第三方包。

## 三、数据说明

| 维度 | 来源 |
| --- | --- |
| ETF / 指数日线（价格、成交量） | 新浪财经（主）、东方财富（备）、腾讯（兜底） |
| 指数真实成交额 | 东方财富 |
| 沪市 ETF 每日总份额 | 上海证券交易所 `query.sse.com.cn` |
| 深市 ETF 历史规模 | 深圳证券交易所 `investor.szse.cn` |
| 十大持有人持仓 | `disclosures.json`（基于定期报告人工整理，脚本自动合并） |

**重要口径**：

- 持仓数据来自基金 **年报 / 半年报** 披露的十大持有人，报告期通常为每年 **12-31 / 6-30**，存在时滞，不能反映实时变动。
- `disclosures.json` 中记录的持仓比例为披露时点值，金额 = 精确份额 × 官方单位净值估算。
- 诚通系（中国诚通 / 北京诚通金控 / 国调基金）直接或部分持有的 ETF 已在页脚备注，**未纳入本仪表盘追踪**。

## 四、本地运行

环境要求：Python 3.8+（无需第三方依赖）。

```bash
# 1. 刷新数据（增量；首次或补全历史可用 --backfill N）
python refresh_data.py
python refresh_data.py --backfill 619   # 回补最近 619 个交易日的真实份额

# 2. 启动本地服务（默认 http://localhost:8300）
python serve.py
# 或直接双击 start_server.bat（Windows）
```

也可直接双击 `start_server.bat` 启动、`stop_server.bat` 关闭。

> 注：本地 `data.js` / `data.json` 为刷新产物；`kline_cache.json` / `shares_cache.json` 为抓取缓存，**删除后下次刷新需重新全量拉取**。

## 五、在线版本与每日自动刷新

- 线上站点（GitHub Pages）：`https://wearehere8.github.io/huijin-tracker/`
- 数据由 **GitHub Actions** 每日 **20:00（北京时间，UTC+8）** 自动刷新并发布，无需本地电脑开机。

**仓库分支策略**：

| 分支 | 内容 |
| --- | --- |
| `main` | 站点代码（HTML / JS / CSS / 配置 / 文档） |
| `data` | 每日刷新产出的数据文件（单条滚动提交，避免仓库历史膨胀） |

部署工作流（`deploy.yml`）在 `main` 或 `data` 更新时，将数据覆盖到代码上并发布到 Pages；刷新工作流（`refresh.yml`）定时运行 `refresh_data.py`，增量更新后推送到 `data` 分支。
